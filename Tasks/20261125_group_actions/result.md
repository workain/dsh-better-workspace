# GUARD-507 — меню групп и выбор группы новой сессии

Задача: https://tracker.yandex.ru/GUARD-507
Ветка: `task/guard-507-group-actions`.

## Требование и границы

В группах сессий внутри workspace нужны доступное контекстное меню, открытие назначенной менеджерской сессии, переименование, создание новой сессии в группе и подгруппы. В пустой новой сессии нужен выбор группы выбранного workspace, включая вложенные и пустые группы и вариант «Без группы».

Меняются только DSH-плагин и его интерфейс. Бизнес-данные, статусы Tracker, платежи, договоры и права Guard не меняются. Существующие сессии не переносятся при установке. Рабочая копия предыдущей задачи с незакоммиченными изменениями оставлена нетронутой.

## Диагностика и критика решения

Независимое ревью подтвердило:

1. Меню использовало `getAnchorRect`, которого нет в установленном Menu rc.5. Реальный контракт — `anchorPoint` для контекстного меню, `anchorRef` для раскрывающегося списка.
2. Общий обработчик назначения менеджера перехватывал действие группы и искал отсутствующий идентификатор сессии. Специальная ветка группы была недостижима.
3. Правый клик был единственным заметным способом вызвать меню; добавлена кнопка «⋯» с доступным названием.
4. Состав группы для менеджера нельзя вычислять из отфильтрованного списка. Проверяется полный рекурсивный состав, точный путь, актуальная привязка и доступность сессии.
5. Создание через обычный `openWorkspace` переиспользовало бы чужую незавершённую сессию. Для команды создания в группе выбран явный fresh create с штатным подключением к workspace.
6. Группы представлены пользовательским заголовком с префиксом, а не отдельной серверной сущностью. Выбор группы закрепляет заголовок и отключает автоматическое название; это ограничение сообщается в интерфейсе.

## Проверки

Выполняются исполняемые тесты реальных обработчиков меню, DOM-компонентов, защиты от устаревшего назначения и выбора группы. Проверка браузером в текущей сессии недоступна: браузерные инструменты не предоставлены. Синтетические DOM-тесты не заменяют визуальную приёмку.

Итоговый `npm test`: **150/150 PASS**, ошибок и пропусков нет. `node --check` для изменённого входа и двух новых модулей — PASS; `git diff --check` — PASS. Независимое повторное code/UX-ревью: принято без блокирующих замечаний, с ограничением отсутствия браузерной проверки.

Пакет `0.41.0-workain.13-guard507.1` собран штатным `npm pack` (27 файлов, оба новых клиентских модуля включены) и установлен через Plugin Manager. Ответ установки: `application: applied`, `warnings: []`. Есть информационное сообщение pnpm о peer dependencies; установка завершена с кодом 0. SHA-256 установленного манифеста и всех изменённых/новых клиентских модулей совпали с проверенной рабочей копией.

Проверка HTTP текущего GUI вернула 401 без браузерной авторизации. Учётные данные не искались, отдельный браузер или сервер не запускались. Это подтверждает доступность защищённого endpoint, но **не** визуальную работоспособность обновлённого интерфейса. Пользователю нужно обновить существующую страницу и проверить меню/выбор группы.

Ширина конкурентного окна: чтение актуального заголовка и проверка expectedTitle выполняются до штатного rename, но это не атомарный серверный CAS. Обнаруженные чужие изменения отклоняются; полная защита от одновременной записи требует поддержки Host API.

Метрики: реализованы оба пользовательских блока; 150 тестов пройдено; 0 блокирующих замечаний повторного ревью; визуальная проверка — не выполнена. Исходники остаются в отдельной task-ветке, основная ветка не менялась.
