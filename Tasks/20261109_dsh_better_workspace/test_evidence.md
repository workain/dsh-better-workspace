# Проверки и воспроизведение

Среда: Node 24.13.1, DSH 0.2.2-rc.1, Chromium через Playwright. Исходная smoke-проверка до изменений: 89/89. Финальная проверка после доработок: 110/110.

Запуск без унаследованных секретов и lifecycle-скриптов:

```sh
env -i HOME="$BW_TEST_HOME" PATH="$BW_NODE_BIN:/usr/bin:/bin" LANG=C.UTF-8 npm test
env -i HOME="$BW_TEST_HOME" PATH="$BW_NODE_BIN:/usr/bin:/bin" LANG=C.UTF-8 npm pack --ignore-scripts --json
BW_SDK="$SDK_RELEASE" BW_PRIVATE="$PRIVATE_ARTIFACTS" BW_NODE="$NODE_BINARY" "$PLAYWRIGHT_PYTHON" tests/e2e/run.py
BW_SDK="$SDK_RELEASE" "$PLAYWRIGHT_PYTHON" tests/e2e/perf.py
```

`BW_PRIVATE` находится вне Git и имеет режим 0700. Runner создаёт новый HOME/DSH_HOME/XDG/cwd, извлекает локальный tarball, использует код установленного SDK и случайный loopback-порт. Дочерний сервер и Chromium получают фиксированный allowlist окружения, без ключей провайдера; внешние HTTP-запросы браузера блокируются. Auth bootstrap остаётся в памяти; сырые журналы и DOM-диагностика — только в приватном каталоге. Общий браузерный сценарий ограничен 180 секундами, запуск сервера — 60 секундами. В finally завершается только собственная группа процессов. Рабочие профили не используются.

Нативные сценарии уже подтвердили: монтирование дерева; назначение и открытие; перезагрузку и отдельный браузерный контекст; пассивное чтение без изменения событий и Agent; публичное переименование с освобождением reference; полное групповое переименование с архивным участником без prompt и снятия архивности; безопасную реакцию на отсутствующую/архивную привязку; очистку с доставкой во второй браузер. Дополнительно пройдены точное переименование двух участников одноимённой группы в собственной дисковой ветке, настоящий popup hero-picker, открытие/отмена штатного directoryFlow, ошибка корня/retry, удаление только регистраций форка, восстановление штатных sidebar/hero и открытие/отмена directoryFlow с исходным владельцем. Неожиданных pageerror: 0.

Корневой сбой внедряется только в извлечённую одноразовую копию через тестовый transform; публикуемый tarball не содержит переключателя ошибки. DOM-утверждения и скриншоты не заменяют визуального ревью человеком.

## Производительность

Индекс подагентов: один проход узлов и рёбер, O(N+E), очередь без shift, циклы ограничены множеством посещённых. Проверки требуют ровно N узлов и N−1 рёбер для цепочки. Наблюдавшееся время для 500/2000/10000: около 0.5/1.8/8.5 мс в одном из запусков; это не универсальный бюджет.

Отдельный Chromium-прогон использует реальные `buildTree` и `WorkspaceRow`, полные каталоги без искусственного лимита и пять обновлений каталога одновременно с кликом стрелки. Не подключает сервер или провайдера.

| Строк | Первое монтирование, мс | Клик с обновлением, диапазон мс |
|---:|---:|---:|
| 500 | 48.8 | 18.4–33.4 |
| 2000 | 41.0 | 37.4–89.9 |
| 10000 | 152.7 | 178.2–462.9 |

Это наблюдения текущего CPU/браузера с ожиданием двух animation frames, а не чистое время обработчика и не SLA. В стресс-каталоге остаются заметные задержки полного React-рендера; функциональность и лимиты ради результата не урезались.

## Границы доказательств

Поведенческие тесты исполняют production chunks и реальные компоненты через VM/React; source smoke дополняет их проверками контрактов. Нативный runner использует исходный SDK, реальные хранилища и Remote, синтетические заголовки и закрытые пустые turns без пользовательских/модельных сообщений. Наблюдение до/после доказывает отсутствие активации Agent и записи при preview; применение штатного rename проверяется отдельно.

Пассивный отказ чтения после первого успешного RPC сохраняет частичный отчёт. Timeout/unknown блокируют повтор до завершения исходной операции; интерфейс не повторяет запись. Проверьте текущее состояние через read-only refresh перед новой осознанной операцией.

Автоматизация не заменяет человеческое визуальное ревью и не доказывает всю ручную матрицу upstream. Нативный restricted-grant пользователь не создавался; отрицательное разрешение проверено на фактическом host-методе с контролируемым remoteAccess.
