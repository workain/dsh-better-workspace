# Разбор рисков

Главные дефекты исходной реализации: глобальный поиск по префиксу пересекает одноимённые группы; фильтрованный список теряет архивных участников; последовательные RPC создают частично выполненные изменения; поглощение корневой ошибки оставляет пустую область.

Нельзя считать displayTitle или локальный кэш источником для записи. Холодные заголовки следует читать пассивно из sessionQuery. Предварительный просмотр не должен активировать Agent. Явное штатное переименование может возобновить Agent, но само не отправляет prompt и не снимает архивность.

Изменения монолитного client.js — ограниченное подключение модулей и замена опасных обработчиков в импортированном универсальном инструменте, который уже превышает лимит размера. Новые файлы должны оставаться короче 600 строк. Переписывание исходного набора возможностей не допускается.

Финальное ревью с точки зрения реализации: точный узел, полный состав и предзаписная сверка необходимы, но не дают транзакции поверх отдельных RPC. С точки зрения пользователя: label, chevron, клавиатура и double-click проверяются раздельно; недействительная привязка требует явного исправления. С точки зрения процесса: успешный HTTP/RPC не заменяет native DOM/readback; все проверки и сбои относятся только к одноразовым данным. Оставшиеся ограничения указаны в result.md, разрешение установки не подразумевается.
